# 五笔码表与拼音反查字典设计

> 本文档对应工程 `ime-harmonyos` 中 `entry/src/main/cpp/core/WubiDict.{h,cpp}` 与
> `entry/src/main/resources/rawfile/`，及方案文档第九章 9.5 的"五笔（编码查表 + 拼音反查）"策略。

## 1. 设计目标

1. 极小内存、微秒级查询：五笔码表约 1 万~6 万词条，远小于拼音词库，单进程常驻内存 ≤ 8MB。
2. 支持 86 与 98 两套编码（可以通过切换码表实现，代码不变）。
3. 提供"字 → 五笔编码"反查索引，用于上屏提示与教学。
4. 提供"拼音 → 字"反查，作为不熟悉编码时的兜底入口（配合前端引导符触发）。

## 2. 编码规则速览（86 版，供数据生成与校验参考）

- 键位：A–Y 共 25 个键，Z 为万能键/反查引导键。
- 单字全码 = 字根按书写顺序取 1、2、3、末根，最多 4 码；不足 4 码补末笔识别码；可配简码（一级/二级/三级简码）。
- 词组规则：
  - 二字词：取首字前两码 + 次字前两码；
  - 三字词：首字首码 + 次字首码 + 末字前两码；
  - 四字及以上：第一、二、三、末字各取首码。
- 注意：同一字在"简码/全码/不同版本"下有多个合法编码，"编码 → 字"为 1 对多，"字 → 编码"亦为 1 对多，必须双向索引。

## 3. 数据格式

### 3.1 码表 tab（`wubi*.txt`，UTF-8）

每行三列，空格分隔：

```
编码  词条  词频
gkhg  或    1000
nnvn  五    900
qyte  你    800
tkgf  五笔  600
```

- 编码统一大写存储（加载时归一化）。
- 词条可以是单字（3 字节 UTF-8）或多字词。
- 词频用于候选排序，来源可以是五笔码表自带的字频 + 自采集的语料统计。

### 3.2 拼音表 py（`pinyin*.txt`，UTF-8）

每行：`单字  拼音1 [拼音2 ...]`（多音字列出全部读音，不带声调）：

```
和  he huo
你  ni
五  wu
```

- 生成工具：`pip install pypinyin`，用 `lazy_pinyin` 批量产出（见第 6 节）。

## 4. 数据结构（对应 `WubiDict.{h,cpp}`）

```
code2words_ : unordered_map<string, vector<WubiEntry>>   // 编码 → 词条(词, 词频)
char2code_  : unordered_map<string, string>              // 单字 → 编码（加载时从单字词条抽取）
char2pinyin_: unordered_map<string, vector<string>>      // 单字 → 拼音列表
```

查询路径：

1. 常规输入：按键字母 → 拼接 code → `Query(code, topN)`：
   先在 `code2words_` 精确命中；候选按词频降序取 Top-N。
   若整码无命中，按编码前缀查找提供"联想"（本骨架暂为精确匹配，扩展点见第 7 节）。
2. 拼音反查：引导符（如按 Z 进入）→ 拼拼音 → `ReverseByPinyin(py, topN)`：
   遍历 `char2pinyin_` 精确匹配读音 → 汇总候选字 → 通过 `char2code_` 取回其五笔编码
   → 展示"字（编码）"，选中后：
   - 模式 A：直接上屏该字；
   - 模式 B：只把编码填入编码区（学习型反查）。
3. 大小写归一：查询入参统一 `UpperAscii`/`LowerAscii` 后再检索（已修复的坑）。
4. 万能键 Z：编码中含 `Z` 时，把每个 Z 替换为 A–Y 任一键做枚举（受 `kMaxWildcardZ` 上限保护），
   合并命中条目后按词频排序返回。用于忘记某字根、或作为"学习键"反向查询整码。

## 5. 容量与复杂度

| 项 | 量级 | 说明 |
| --- | --- | --- |
| 词条数 | 1 万~6 万 | 五笔核心词表 |
| 内存 | 约 3–8MB | unordered_map 指针开销可接受；后续可换 marisa-trie/DAWG 压缩 |
| 单查耗时 | 微秒级（O(1) 哈希） | 无需 Trie 前缀遍历 |
| 反查耗时 | 遍历 1 万~2 万单字 | 仅在反查时用；若卡顿可在加载时建立 `拼音 → 字列表` 正向索引 |

建议优化（二期）：加载时同时建 `pinyin2chars: unordered_map<string, vector<string>>`，把反查从 O(全部单字) 降到 O(最近拼音命中)，结构上只需要在 `Load()` 内多一次反转。

## 6. 码表构建工具（Python，配合你的现有栈）

```python
# gen_wubi_tables.py —— 生成 wubi_sample/full 与 pinyin 表
from pypinyin import lazy_pinyin

def normalize(code: str) -> str:
    return code.strip().upper()

def build_pinyin_table(chars: list[str], out: str):
    with open(out, "w", encoding="utf-8") as f:
        for ch in chars:
            pys = sorted(set(lazy_pinyin(ch)))
            if pys:
                f.write(f"{ch} {' '.join(pys)}\n")

if __name__ == "__main__":
    # 1) 从五笔码表 txt 直接生成 tab 文件（源数据获取：五笔码表开源数据集/自建字根拆分）
    with open("wubi_full.txt", "r", encoding="utf-8") as f:
        lines = (l.strip().split() for l in f if l.strip())
        data = [(normalize(c), w, int(n)) for c, w, n in lines]
    with open("wubi_full.tab", "w", encoding="utf-8") as f:
        for c, w, n in data:
            f.write(f"{c} {w} {n}\n")
    # 2) 取正文高频字生成拼音表
    chars = sorted({w for c, w, n in data if len(w.encode("utf-8")) == 3})
    build_pinyin_table(chars, "pinyin_table.txt")
```

完整码表获取建议：

- 优先使用 GPL/MIT 开源的五笔码表数据集（如极点五笔词库等公开资源），核对许可证后再打包进 App。
- 若自建，用字根拆分表（86 版五笔字根 25 个键位归类）+ 词组规则（第 2 节）离线生成。

## 7. 关键坑位与规避

| 坑 | 说明 | 规避 |
| --- | --- | --- |
| 大小写不一致 | 码表大写、用户按键小写 | 加载与查询两侧统一 `UpperAscii`（已在代码修复） |
| 多音字 | "和 he/huo/hè" | py 表列全部读音；反查按任一读音命中 |
| 简码/全码冲突 | 同字多码 | `char2code_` 保留全码；前端可展示多编码 |
| 万能键 Z | 86 版 Z 兜底匹配任意键 | 已实现：`Query` 对含 Z 编码枚举 A–Y，`kMaxWildcardZ` 限制组合爆炸 |
| UTF-8 切分 | 用 `size()==3` 判单字 | 仅用于 ASCII 编码 vs 中文词条的区分，避免误判 |
| 词组与单字优先级 | 输入 4 码可能同时是词与字 | 词频直接排序，用户词频学习可上移 |

## 8. 与前端交互设计

- 编码区（Composing）：按键输入时追加到 buffer，实时 `wubiQuery` 刷新候选栏。
- 反查区：用户按引导键（Z 或设置页开启"扫出反查"）后 buffer 前加前缀 `@`，前端展示拼音候选，
  选中后把 `字 + 编码` 显示在候选条首行供选择。
- 上屏事件：与拼音模式一致，走 `KeyboardController.insertText({ text })`，
  并调用 `EngineBridge.learn(text)` 记录用户词频。
- 个性化：用户词频存本地（Preferences/RelationalStore），每次查询用 0.3 加权（详见
  `EngineCore.cpp Decode()` 的 `user_freq_` 逻辑），并提供一键清除入口（设置页已提供）。
